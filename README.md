# The Collection

An AMOLED black/white catalog and marketplace for your shoe and clothes collection, with customer accounts, a saved basket and wishlist, delivery addresses, order tracking, seller tools, shipper fulfillment, and a password-protected admin panel.

## Setup (in VS Code)

1. Open this folder in VS Code.
2. Open a terminal (``Ctrl+` `` / ``Cmd+` ``) and install dependencies:
   ```
   npm install
   ```
3. Configure Firebase Admin credentials and the Resend settings described below. Enable Firebase Authentication's **Email/Password** provider and add your site domain to its authorized domains. The bootstrap admin email is `nsmskipruto@gmail.com`; use **Forgot Password?** on the admin sign-in page to set its Firebase password.
4. Start the server:
   ```
   npm start
   ```
5. Open the site:
   - Gallery: http://localhost:3000
   - Customer and marketplace accounts: http://localhost:3000/account.html
   - Admin panel: http://localhost:3000/admin.html

The local `.env` file contains the server port and seller WhatsApp number. It is ignored by Git and should never be committed.

Customer and admin password reset links are generated by Firebase Authentication and delivered through Resend. Configure `RESEND_API_KEY`, `RESEND_FROM_EMAIL` (a verified sender), and `PUBLIC_BASE_URL` (the site's public HTTPS origin) in `.env` or your hosting provider. Reset requests return a generic response so they do not reveal whether an email belongs to an account.

If sign-in reports an invalid email/password, first check the email and password carefully. Accounts created before Firebase Authentication was enabled must use **Forgot password?** once to set a Firebase password; their saved marketplace data is retained. If password recovery reports that it is not configured, check the server logs for missing Firebase or Resend configuration and set the required environment variables above. Also confirm **Email/Password** is enabled in the same Firebase project configured in `public/js/firebase.js`, and that the deployed site domain is listed under Firebase Authentication's authorized domains.

## M-Pesa Daraja checkout

The storefront uses Daraja STK Push. Add these values to `.env` for local testing or configure them as secrets in your hosting provider:

```env
MPESA_ENVIRONMENT=sandbox
MPESA_CONSUMER_KEY=your_daraja_consumer_key
MPESA_CONSUMER_SECRET=your_daraja_consumer_secret
MPESA_PASSKEY=your_stk_push_passkey
MPESA_SHORTCODE=174379
MPESA_TRANSACTION_TYPE=CustomerPayBillOnline
MPESA_CALLBACK_URL=https://your-public-domain.example/api/mpesa/callback
```

Create an app in the Safaricom Daraja portal to obtain the consumer key and secret. Use the matching sandbox or production shortcode and passkey. The callback URL must be publicly reachable over HTTPS; local `localhost` URLs cannot receive Daraja callbacks. Set `MPESA_ENVIRONMENT=production` only after the production app and shortcode are approved.

## Marketplace accounts and roles

Customers can create an account at `/account.html` to keep a basket and wishlist, manage delivery addresses, and track paid M-Pesa orders. Customer and admin passwords are managed by Firebase Authentication; account profiles and marketplace roles remain in Firestore. Email verification is required before sign-in. Customers can apply to become sellers; an admin approves seller, shipper, and additional admin roles from **Marketplace** in the admin panel or account page. Sellers manage their own products and shipping queue, while shippers only receive orders assigned to their configured delivery area.

Marketplace data uses Firestore when Firebase credentials are configured. It is stored in the `marketplace_users`, `marketplace_carts`, `marketplace_wishlists`, `marketplace_addresses`, `marketplace_orders`, `marketplace_shippers`, and `marketplace_categories` collections. Passwords are never stored in marketplace profile documents. Existing marketplace profiles and their order/cart references are preserved; when a customer verifies their email after registration or password recovery, their Firebase identity is linked to their existing profile.

Existing marketplace passwords cannot be imported into Firebase. Customers with an older account should use **Forgot password?** to set a Firebase password; their saved account data and role are retained.

The browser signs customers in with Firebase Authentication ID tokens, which the server verifies before account operations. Admin pages continue using short-lived in-memory admin sessions after Firebase sign-in. Paid M-Pesa checkouts create order records for signed-in customers and guest purchases alike, but only signed-in customers can view their order history.

## How it works

- **Catalog data** lives in Firestore's `products` collection when Firebase is configured, or `data/items.json` in local fallback mode.
- **Marketplace accounts and order data** use the Firestore collections documented above; account sign-in requires Firebase Authentication and Firestore credentials.
- **Images** you upload through the admin panel are saved into `public/uploads/`.
- **Admin sessions** are simple in-memory tokens issued after Firebase Authentication; restarting the server signs admins out.
- The public gallery (`/`) only ever reads data — nothing there can add, edit, or delete anything.

## Adding items

Go to the admin panel, sign in, and use the "Add a new item" form. Each item has:
- **Name** and **category** (shoes / clothes) — required
- **Quantity in stock** — a non-negative whole number; positive quantities are in stock and zero is sold
- **Status** — In the archive is a manual override available from the item form or table
- **Price** and **caption** — optional
- **Image** — optional, shown as a placeholder card if left off

## Deploying it live
Only in-stock items can be added to the basket or checked out with M-Pesa. Sold and archived items remain available for WhatsApp inquiries. Basket quantities cannot exceed available stock, and successful M-Pesa payments reduce the stored quantity.


This is a small Node app, so it deploys easily to something like Render, Railway, or a VPS — anywhere that can run `npm install && npm start` and keep a persistent disk for `data/` and `public/uploads/`. (Free static hosts like Netlify/Vercel won't work as-is since this needs a running Node server, not just static files.)

### Render

1. Push this project to a GitHub repository.
2. In Render, choose **New > Blueprint**, connect the repository, and select `render.yaml`.
3. Set the secret environment variables when Render prompts you:
   - `SELLER_PHONE_NUMBER` = `254728074301`
   - `API_SECRET_KEY` = a private random value
   - `CLOUDINARY_CLOUD_NAME` = your Cloudinary cloud name
   - `CLOUDINARY_API_KEY` = your Cloudinary API key
   - `CLOUDINARY_API_SECRET` = your Cloudinary API secret
   - `FIREBASE_SERVICE_ACCOUNT` = the Firebase service-account JSON as a single-line value
   - `RESEND_API_KEY` = a Resend API key
   - `RESEND_FROM_EMAIL` = a verified sender address, for example `The Collection <admin@example.com>`
   - `PUBLIC_BASE_URL` = the public site origin, for example `https://your-site.onrender.com`
4. Deploy the web service. Render provides the public URL after the build finishes.

The included `render.yaml` configures `npm install`, `npm start`, and a 1 GB Persistent Disk mounted at `/opt/render/project/src/storage`. When the three Cloudinary variables are set, new admin uploads are stored in the `shoe_collection` Cloudinary folder and use permanent Cloudinary URLs. Without them, the app falls back to the persistent disk and `/uploads/<filename>` URLs. Existing local images must be uploaded again through the admin panel after the first deployment. Persistent disks are tied to one service instance; Cloudinary is preferred for multi-instance deployments.

When `FIREBASE_SERVICE_ACCOUNT` is configured, catalog records are stored in the Firestore `products` collection and M-Pesa transaction status is stored in `mpesa_transactions`. Enable **Email/Password** under Firebase Authentication → Sign-in method, and add the deployed site domain to Firebase Authentication's authorized domains. The Firebase Web API key in `public/js/firebase.js` is intended for browser use; keep the service-account credentials private and configure them only on the server. For local development, place the downloaded service-account file at `firebase-key.json`; it is ignored by Git.

Signed-in admins can open **Transactions** from the admin navigation to view completed M-Pesa payments, including buyer details and item quantities. This history requires working Firestore credentials; pending and failed payments are not listed.

## Customizing the look

All colors, type, and spacing live in `public/css/style.css` under the `:root` block at the top — change the hex values there to retheme the whole site at once.
